# Публикация на Vercel

Публикация в production в рамках разработки не выполнялась. Перед первым деплоем нужны аккаунт Turso, проект Vercel, боты MAX и Telegram и значения переменных окружения.

## 1. База Turso

Создайте базу libSQL и получите URL и токен. Добавьте в Vercel:

- `TURSO_DATABASE_URL`;
- `TURSO_AUTH_TOKEN`.

При первом обращении приложение само создаст таблицы. Если `OWNER_PIN` не задан, первая комната создаётся через публичную кнопку «Создать комнату». Каждая новая комната получает собственные строки карты, заданий, наград, игроков, сезонов и уведомлений.

Текущую локальную тестовую комнату перед первым production-запуском нужно перенести в Turso целиком, а не создавать заново: именно в ней находится рабочая история. Перед импортом сохраните проверенную копию `data/preview-clean.db`, перенесите все таблицы и только затем переключайте `TURSO_DATABASE_URL`. Миграции приложения добавляют новые столбцы без удаления существующих строк.

## 2. Обязательные секреты

- `SESSION_SECRET` — случайная строка не короче 32 символов;
- `PUBLIC_APP_URL` — итоговый адрес `https://...vercel.app`;
- `CRON_SECRET` — секрет вызова планировщика.

`OWNER_NAME` и `OWNER_PIN` нужны только для необязательного автоматического создания демонстрационной/первой комнаты в пустой базе. Для публичного создания комнат их можно не задавать.

PIN не хранится открытым текстом: в базе сохраняются соль и вычисленный хеш. Сессионный cookie имеет флаги HTTP-only, SameSite и Secure в production.

## 3. MAX и Telegram

Глобально в Vercel достаточно оставить адрес MAX API:

- `MAX_API_BASE=https://platform-api2.max.ru`;

Токены и chat ID MAX/Telegram вводятся руководителем в кабинете конкретной комнаты. Они хранятся в строке этой комнаты и никогда не используются уведомлениями другой комнаты. Если канал не заполнен, он пропускается без ошибки игрового действия.

Переменные `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` оставлены только для однократного переноса настроек старой единственной комнаты. Для новых комнат они не используются.

Каждое игровое событие отправляется в оба канала независимо. Ошибка одного канала не блокирует второй и не отменяет игровое действие. Без реквизитов конкретного канала игра продолжает работать, а его уведомления помечаются как пропущенные.

Ежедневная сводка вызывается отдельным защищённым endpoint `/api/cron/digest` в 00:05 по Москве и всегда считает полностью завершившийся предыдущий день. Повторный вызов до 00:15 безопасен: ключ события не позволит отправить одну и ту же сводку дважды. Расписание Vercel хранится в UTC (`21:05` = `00:05` по Москве); позднее этот же endpoint можно вызывать внешним cron-сервисом с `CRON_SECRET`.

## 4. Ссылки для задания с отзывом

Заполните только точные карточки соответствующей студии:

- `NEXT_PUBLIC_REVIEW_YANDEX_MACHUGI`;
- `NEXT_PUBLIC_REVIEW_2GIS_MACHUGI`;
- `NEXT_PUBLIC_REVIEW_GOOGLE_MACHUGI`;
- `NEXT_PUBLIC_REVIEW_YANDEX_STAVROPOLSKAYA`;
- `NEXT_PUBLIC_REVIEW_2GIS_STAVROPOLSKAYA`;
- `NEXT_PUBLIC_REVIEW_GOOGLE_STAVROPOLSKAYA`.

Незаполненные платформы просто не показываются игроку.

## 5. Резервные копии

Подключите Vercel Blob и добавьте `BLOB_READ_WRITE_TOKEN`. Ежедневный cron создаёт приватную сжатую логическую копию таблиц и оставляет последние 14 файлов. Если Blob не подключён, endpoint вернёт ошибку конфигурации; основная игра продолжит работать в Turso.

## 6. Проверка перед публикацией

```powershell
npm ci
npm run typecheck
npm run lint
npm test
npm run test:scenario
npm run test:multiroom
npm run build
```

После деплоя проверьте по порядку:

1. создание отдельной комнаты через публичную кнопку;
2. наличие в ней стартовой карты, заданий и наград;
3. копирование общей ссылки комнаты и создание игрока с PIN;
4. вход игрока по общей ссылке и личному PIN;
5. изменение одной клетки и подтверждение, что карта другой комнаты не изменилась;
6. начисление и отмену тестового броска;
7. один реальный бросок;
8. сохранение и тест MAX/Telegram отдельно в каждой комнате;
9. ручной защищённый вызов endpoints напоминаний, ежедневной сводки и резервной копии;
10. наличие файла копии в Blob и строк всех комнат в Turso.

Перед приглашением команды замените временный PIN владельца и сохраните production-секреты вне репозитория.
